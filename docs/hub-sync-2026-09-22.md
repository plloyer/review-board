## 1. Data model additions on a card

```js
agent: { vendor: "claude" | "codex" | "antigravity", model: string, effort?: string }  // who works it
tags: string[]                  // lowercased, deduped, absent when empty; who CAN take it
images: [{ path, label?, caption? }]   // label = short tag (Before / After / Original), caption = one sentence; a video path (.mp4/.webm/.mov) may sit in this same list
```

## 2. shared/agents.js (new, load in Node and browser like lifecycle.js)

```js
"use strict";
(function () {
const AGENT_VENDORS = {
  claude: { icon: "agents/claude.svg", label: "Claude" },
  codex: { icon: "agents/codex.png", label: "Codex" },
  antigravity: { icon: "agents/antigravity.png", label: "Antigravity" },
};
function agentRequiredText(id) {
  const vendors = Object.keys(AGENT_VENDORS).map((v) => `"${v}"`).join("|");
  return `${id} cannot enter in_progress without agent: {vendor: ${vendors}, model: "<your model>", effort: "<your effort setting, optional>"} so the board shows who is working the card`;
}
const Agents = { AGENT_VENDORS, agentRequiredText };
if (typeof module !== "undefined") module.exports = Agents; else window.Agents = Agents;
})();
```

Served under `/shared/agents.js`, script tag right after `shared/lifecycle.js`, required by `server/store.js` (agentRequiredText), `server/mcp.js` (AGENT_VENDORS for the zod enum) and `public/views.js`.

## 4. Store rules (server/store.js)

- `moveTask(id, state, note, { blockedBy, priority, actor, agent, tags })`:
  - Gates in this order, all before any mutation: approval (existing), retro (existing), then `if (actor === "agent" && newState === "in_progress" && !agent && !msg.agent) throw new Error(agentRequiredText(id))`.
  - `assignBlockers` runs into a local before `msg.state = newState`; a bad `blocked_by` leaves the card untouched.
  - After the state change: `if (newState === "backlog") delete msg.agent; if (agent) msg.agent = agent;` then `tags !== undefined` sets normalized tags or deletes the field when the list normalizes to empty.
- `agentReply(id, text, kind, { retro, agent })`: `if (agent) msg.agent = agent`.
- `reopen(id)`: `delete msg.agent` next to `msg.state = "backlog"`.
- `createTask({..., tags})`: stores `normalizeTags(tags)`.
- `addHumanMessage(text, ...)`: `tags = tagsFromText(text)` with `/(?:^|\s)#([a-z0-9][a-z0-9-]*)\b/gi`, text left untouched.
- `normalizeTags`: trim, lowercase, drop empties, dedupe, `undefined` when empty.

## 5. MCP (server/mcp.js), tools v7

- `AGENT_SCHEMA`: `z.object({ vendor: z.enum(Object.keys(AGENT_VENDORS)), model: z.string().trim().min(1), effort: z.string().optional() }).optional()`; on `move_task` and `reply_to_message`. No handler-side gate: the store throws and the SDK turns it into `isError`.
- `TAGS_SCHEMA`: `z.array(z.string()).optional()`; on `create_task` and `move_task`.
- `send_message` images: `z.object({ path, label: z.string().optional(), caption: z.string().optional() })`.
- `list_messages` row: append ` tags: a,b` when present (after the ` pN` suffix).
- `pushImages` (delivery): a video path pushes one text block `attached video: <name> (<path>)` and no image block.
- `/api/upload` (web.js): regex `^data:(image|video)\/(\w+);base64,(.+)$`, default filename `${kind}.${ext}`.
- Instruction lines added to WORKFLOW_INSTRUCTIONS (and WORKFLOW.md):
  - "Start a card: move_task in_progress with agent {vendor, model, effort} (required the first time: it draws who works the card; reply_to_message also takes agent when a card changes hands)."
  - "Tags (create_task/move_task tags, listed by list_messages as tags: a,b) say who CAN take a card: windows / mac / linux, unity (needs a Unity pass), or a machine name. Never start a card whose tags exclude your machine; no tag = anyone."
  - "Every proof image is labelled: ![Before](/api/image?path=<enc> \"one sentence on what it shows\") - alt = short tag, quoted title = what the image shows; both appear over the zoomed image."
- Tool descriptions: move_task mentions "Entering in_progress requires agent {vendor, model, effort} unless the card already carries one"; reply_to_message asks to label every embedded image.

## 8. Attachments

- `imagesHTML(images, msgId)`: video path → `<video class="thumb-video" src="/api/image?path=…" controls preload="metadata"></video>`; image → `<img src class="thumb" [data-msg-id] [alt=label] [title=caption]>`.
- Pending chips: `<video src preload="metadata" muted>` for a video path, `<img>` otherwise; `.pending-chip img, .pending-chip video { width: 60px; height: 45px; object-fit: cover; border-radius: 4px; border: 1px solid #444; display: block; }`, `.thumb-video { max-width: 100%; max-height: 360px; border-radius: 6px; display: block; }`, `.images .thumb-video { max-width: 320px; max-height: 240px; border: 1px solid #444; }`.
- Drop filter `/^(image|video)\//`, attach inputs `accept="image/*,video/*"`, paste stays image-only.
- `addPendingImage` and every attach/remove/send path repaint EVERY `.pending-row[data-pending-key=key]` (board card and open overlay share keys).
- Unavailable image placeholder: `🖼️ image indisponible (<src, 60 chars>)` with the full src in `title`.
